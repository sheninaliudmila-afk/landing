# Размещение FINCONSULT

## Статический лендинг

Новая публикация рассчитана на статический хостинг, включая GitHub Pages. HTML, CSS, JavaScript и медиа можно разместить на домене. GitHub Pages не выполняет TanStack server functions и серверную отправку почты.

По умолчанию форма работает в учебном режиме: на странице показано «Учебная версия: отправка заявок пока не подключена», кнопка «Сохранить заявку» скачивает TXT-файл на устройство посетителя. Автоматическая передача заявки консультанту не выполняется. Имя, email, задача и подтверждение согласия включаются в локальный файл. Сохранение в localStorage не используется.

## Подключение настоящего приёма заявок

1. Разверните отдельный HTTPS API, например в Cloudflare Worker. Настройте хранение заявок и серверные переменные окружения.
2. Скопируйте `.env.example` в `.env.local` и укажите `VITE_CONTACT_ENDPOINT=https://ваш-api/contact`.
3. Пересоберите и опубликуйте сайт. Значение `VITE_CONTACT_ENDPOINT` публично и встраивается в JavaScript при сборке.
4. Проверьте разрешённые origin в CORS для GitHub Pages, опубликованного сайта и своего домена. API должен обрабатывать OPTIONS и POST с JSON. Cookie и Authorization из браузера адаптер не передаёт.

Контракт запроса:

```json
{
  "name": "Имя клиента",
  "email": "client@example.com",
  "message": "Задача и выбранные услуги",
  "consent": true
}
```

Сервер обязан независимо валидировать поля, требовать `consent: true`, ограничивать частоту/размер запросов и записывать заявку перед подтверждением. Рекомендуется хранить дату согласия и версию текста согласия. Настройку согласия и политики обработки данных необходимо завершить до подключения реальных заявок.

Успешный ответ: HTTP 200/201, `Content-Type: application/json`, тело `{"id":"UUID-сохранённой-заявки"}`. Адаптер проверяет UUID, поэтому произвольная страница с HTTP 200 не считается подтверждением. Ответ означает сохранение заявки; доставку email он не гарантирует. Ошибки: 400/422 для некорректных данных, 429 для ограничения частоты, 5xx для временной недоступности. Клиент ожидает подтверждение до 15 секунд. При тайм-ауте запись могла состояться; это явно указано посетителю.

`VITE_*` доступны всем посетителям. Не добавляйте в них `LOVABLE_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, пароли или иные секреты. Ключи почты и административного доступа к БД хранятся только на сервере. Секрет в публичном репозитории или JavaScript перестаёт быть секретом.

## Исходная серверная часть из архива

Код TanStack Start сохранён в исходниках как основа для полноценного серверного развёртывания: `src/lib/contact.functions.ts`, `src/lib/contact-notifications.server.ts`, `src/lib/email-templates/`, `src/integrations/supabase/`, `src/server.ts`, `src/start.ts`. Статическая форма вызывает отдельный адаптер `src/lib/contact-client.ts`; она не импортирует серверную функцию.

Исходная функция валидирует поля через Zod, вставляет заявку в `contact_submissions` и пытается отправить два уведомления через Lovable Email. Она возвращает успех после записи в БД даже при сбое уведомлений. В архиве нет значений переменных окружения, SQL-миграций и политик RLS. Работоспособность Supabase, разрешение вставки и подтверждение доменов отправителя не установлены.

Для возвращения исходного серверного приложения нужен отдельный TanStack Start/Nitro deployment, например на Cloudflare Workers, с настройкой окружения. Для текущего кода требуются `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` и `LOVABLE_API_KEY`; `LOVABLE_SEND_URL` опционален. `SUPABASE_SERVICE_ROLE_KEY` предусмотрен admin-клиентом, но исходная форма его не использует.

Перед использованием исходного обработчика добавьте серверную проверку и хранение согласия: текущая схема `contact-schema.ts` согласие не сохраняет. Проверьте таблицу, RLS, ограничения частоты и настройку почты. Нельзя просто включить исходный TanStack URL в качестве внешнего API: ему нужен отдельный HTTP-обработчик с указанным выше JSON-контрактом и CORS.

Реальные заявки и письма при подготовке этой версии не отправлялись. Изменения кода и локальные тесты не подтверждают доставку почты.
